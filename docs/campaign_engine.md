# ConvoSpan Campaign Engine Specification

## Purpose

The Campaign Engine orchestrates autonomous outreach workflows across multiple communication channels.

It converts signal intelligence and lead context into structured outreach sequences executed by Edge Nodes.

The engine ensures campaigns remain adaptive, safe, and human-like.

---

# Core Concepts

## Campaign

A campaign represents a structured outreach strategy targeting a specific audience.

Attributes:

```id="a1c1"
campaign_id
team_id
campaign_name
target_icp
status
budget
start_date
```

---

## Sequence

A sequence is a series of actions executed over time.

Example sequence:

```id="a1c2"
Day 1 → Visit LinkedIn profile
Day 2 → Send connection request
Day 4 → Send first message
Day 7 → Send follow-up message
```

Sequences are represented as a **Directed Acyclic Graph (DAG)**.

---

## Workflow Node Types

Each node in the DAG represents an action or logic condition.

### Action Nodes

These perform external actions.

Examples:

```id="a1c3"
linkedin_visit
linkedin_connect
linkedin_message
email_send
whatsapp_message
```

---

### Logic Nodes

These evaluate conditions before continuing.

Examples:

```id="a1c4"
if_reply_received
if_connection_accepted
if_meeting_booked
```

---

### Delay Nodes

Delay nodes introduce time intervals between actions.

Example:

```id="a1c5"
delay_days = 2
```

```id="a1c6"
define ICP

```

Signals generated by the Signal Graph can automatically trigger campaigns.

Example:

Signal detected:

```id="a1c7"
facility expansion
```

Campaign trigger:

```id="a1c8"
target plant heads
```

Generated workflow:

```id="a1c9"
visit profile
send connection
discuss operational scaling
```

---

# Lead Assignment

Leads are assigned to campaigns using qualification scores.

Criteria:

```id="a1c10"
ICP match
signal strength
intent score
```

Only leads exceeding a threshold enter campaigns.

Example:

```id="a1c11"
score ≥ 70
```

---

# Task Generation

Each campaign node produces automation tasks.

Example:

Node:

```id="a1c12"
linkedin_connect
```

Generated task:

```json
{
  "action": "linkedin_connect",
  "payload": {
    "profile_url": "linkedin.com/in/example",
    "message": "Hi <PERSON_1>"
  }
}
```

Tasks are sent to the Redis queue.

---

# Task Dispatch Flow

Campaign engine dispatch flow:

```id="a1c13"
campaign node ready
→ generate task
→ push to queue
→ edge node claims task
→ execution result returned
```

---

# Conversation State Management

Each lead maintains a conversation state.

Possible states:

```id="a1c14"
NEW
CONNECTED
MESSAGE_SENT
REPLIED
MEETING_BOOKED
NOT_INTERESTED
```

Campaign logic uses these states to determine the next action.

---

# Reply Handling

Replies are processed by the Reply Intelligence Agent.

Example classification:

```id="a1c15"
POSITIVE
CURIOUS
NEED_INFO
NOT_INTERESTED
```

Actions triggered:

```id="a1c16"
positive → meeting agent
curious → conversation agent
not_interested → stop sequence
```

---

# Meeting Scheduling

When a prospect expresses interest:

```id="a1c17"
generate calendar link
send scheduling message
update state = MEETING_BOOKED
```

---

# Campaign Limits

To prevent spam behavior, campaigns enforce limits.

Daily limits per account:

```id="a1c18"
connections ≤ 30
messages ≤ 60
profile_visits ≤ 150
```

Limits may vary by platform.

Metrics:

Rules:


If safety risks are detected:

```id="a1c24"

```
